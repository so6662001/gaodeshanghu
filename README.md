# 货袋子增长运营平台

用高德关键字采集精准商户线索，经清洗分层后通过创蓝 253 批量短信触达，
并把「发送 → 点击 → 注册 → 首单」全链路归因串起来的一套商户增长系统。

解决的是同一个问题：**怎么让更多买家进货袋子平台，并且能算清楚每一分钱花在哪。**

---

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置
cp .env.example .env
#    至少填写 AMAP_KEY（高德 Web 服务 Key）
#    创蓝账号可以先不填，系统默认演练模式不会真实发短信

# 3. 灌入演示数据（可选，没有高德 Key 也能先看到平台全貌）
python scripts/seed_demo.py

# 4. 启动
uvicorn app.main:app --reload --port 8000
```

打开 <http://127.0.0.1:8000>，第一件事去「通道设置」页填入 `.env` 里的 `ADMIN_TOKEN`，
否则所有接口都会返回 401。API 文档在 <http://127.0.0.1:8000/docs>。

### 上线前的检查清单

| 项目 | 位置 | 说明 |
| --- | --- | --- |
| 高德 Key 可用 | 通道设置页 | Key 必须选「Web服务」平台，选成 JS API 会报 10009 |
| 创蓝账号可用 | 通道设置页 | API 密码不是登录密码，需在创蓝控制台单独查看 |
| 短信签名已报备 | `.env` 的 `SMS_SIGN` | 未报备的签名会被运营商直接拦截 |
| 回调地址已配置 | 创蓝控制台 | 状态报告 + **上行回复**，后者不配退订就无法自动生效 |
| 测试短信已收到 | 通道设置页 | 先发一条到自己手机，确认签名、错别字、链接跳转 |
| 关掉演练模式 | `.env` 的 `SMS_DRY_RUN=false` | 确认以上全部通过后再关 |

## 完整运营流程

### 第一步：试搜，别急着跑全量

进「商机采集」，填关键词和城市，先点**「先试搜 10 条」**。

重点看返回的**手机号覆盖率**。不同品类在高德挂手机号的比例差别极大：
连锁餐饮门店常常只挂 400 总机，夫妻店反而更多挂老板手机。
覆盖率低于 30% 的品类，短信这条路走不通，应该转给 BD 扫街。

这一步能避免把高德配额和短信预算浪费在根本触达不到的品类上。

### 第二步：正式采集

三种采集方式，按目标选：

| 方式 | 适用场景 | 上限 |
| --- | --- | --- |
| **关键词** | 快速试水某个城市的某个品类 | 高德硬上限 1000 条 |
| **网格化** | 要把一个城市的某品类扫全 | 把城市切成 N×N 格逐格搜，4×4 网格理论上限 16000 条 |
| **周边** | 圈定某个商圈、批发市场、写字楼扫街 | 半径最大 50km |

高德对单个查询条件最多只返回前 1000 条，这是网格化存在的唯一原因。
注意网格越密消耗的配额成倍增加，个人开发者 Key 日调用量只有 3000 次，
跑 4×4 网格 + 10 个关键词就要 1600 次请求，先算好账。

采集过程自动完成：号码拆分清洗（座机/手机分开）、三层去重、价值打分分级。

### 第三步：看商户库，理解你手里的牌

商户按 S/A/B/C 四级排序，评分逻辑：

```
可触达性 35 分  有手机号才谈得上短信增长，只有座机的最多拿 12 分
品类匹配 25 分  餐饮 25 / 零售 22 / 住宿 16 ...  货袋子是食材供应链，餐饮零售才是真买家
经营体量 20 分  人均消费越高、是连锁门店，采购规模越大
活跃质量 20 分  高德评分、营业时间、信息完整度，反映门店是否在正常经营
```

**S 级（80 分以上）建议短信 + BD 电话双线跟进，C 级不值得花短信钱。**
这是美团 BD 体系里最朴素也最有效的一条经验：把有限资源压在高价值池上，
ROI 会有数量级的差异。

### 第四步：写文案

系统预置了四套文案（首触/二触/三触/唤醒），直接改比从零写快。写文案三个要点：

1. **第一句点名门店**。「老张火锅老板您好」和「尊敬的商户」，回复率不是一个量级。
   这就是为什么要做变量短信而不是统一群发。
2. **给可量化的利益点**。「平均降低采购成本 15%」远好过「优质货源」。
   老板每天收几十条推销短信，抽象的形容词一秒就被划过去。
3. **结尾给低门槛动作**。「点开看您门店的专属报价」，不要一上来就要求注册。

模板编辑页右侧有实时预览和**合规提醒**，会提示敏感词、缺退订、超长计费等问题。
超过 70 字就按两条计费，预算直接翻倍，写之前先看清楚字数。

### 第五步：建活动，先灰度

建活动时做三件事：

- **圈人**：按城市、品类、评级、是否触达过筛选。点「预估人数」看清楚要打多少人。
- **A/B 分流**：至少配两版文案，权重各半。同一商户会稳定落在同一版，
  不会出现二次触达文案跳变的情况。
- **跟进节奏**：开启后，对「已送达但没点击」的商户在 N 天后自动发下一轮。
  已经点过链接或回复过的商户不再打扰，交给 BD 跟人。

**第一次务必只圈 200 家 S 级商户做灰度。** 看点击率再决定放量：

| 点击率 | 判断 | 动作 |
| --- | --- | --- |
| > 8% | 文案打中痛点 | 放量，把预算压到赢的那版 |
| 3% ~ 8% | 正常水平 | 继续 A/B 优化文案 |
| < 3% | 文案或人群有问题 | 停下来换文案，别急着烧量 |

创建后点「圈人」生成队列，再点「启动」。调度器会在发送时段内按日限额自动发出，
也可以点「立即发一批」手动灰度。

### 第六步：看漏斗，找问题

「增长概览」的转化漏斗告诉你问题出在哪一层：

| 现象 | 病根 | 处方 |
| --- | --- | --- |
| 可触达率低 | 该品类高德不挂手机号 | 换品类，或转 BD 扫街 |
| 送达率 < 90% | 号码质量差或通道有问题 | 检查失败回执，空号会自动标记作废 |
| 点击率低 | 文案没打中痛点 | 换 A/B 版本，别改落地页 |
| 注册率低 | 落地页或承接流程有问题 | **不是短信的锅**，去查落地页转化 |
| 首单率低 | 新客激励不够 | 加首单立减、免配送费 |

## 合规红线（不可妥协）

营销短信是强监管业务。投诉率超标运营商会直接封停通道，整个增长链路瘫痪。
这几条系统里是硬编码强制执行的，改配置可以放宽，但强烈建议不要动：

1. **退订即止**：商户回复 T/TD/退订自动进黑名单，永久停发且**不允许移出**。
2. **时间窗**：默认只在 09:00–20:00 发送，其余时间队列自动顺延到次日早上。
3. **频次控制**：同一号码 7 天内不重复触达，30 天内最多 3 次。
4. **必带退订**：每条营销短信自动追加「回T退订」后缀。
5. **只发手机号**：座机和 400 号码一律拦截，转 BD 电销工单。

所有拦截都会记录原因，在活动报表的「合规拦截明细」里可以看到。
**拦截不是浪费，是在保护通道和品牌。**

另外，商户手机号属于个人信息：接口全部需要 Token 鉴权，
列表和导出默认脱敏，需要完整号码要显式加参数并留审计日志。

## 三个高价值的运营玩法

这三个都是从美团商户运营体系里借来的，投入产出比最高：

**1. 三轮触达法**
首触讲价值（省多少成本）→ 3 天后二触给具体让利（首单立减 200）→
7 天后三触做同商圈案例（您商圈已有 37 家在用）。
单轮触达的转化率通常只有三轮组合的三分之一，但一定要只对没响应的商户跟进。

**2. 商圈密度攻坚**
不要在全城撒网。选一个商圈，把该商圈的目标品类打穿（覆盖率做到 80% 以上），
再让 BD 上门。同商圈的商户互相认识，形成密度后口碑传播的效率远高于短信本身。
「商户分布」按区县/商圈维度看，就是为这个准备的。

**3. 意向线索当天流转**
「触达记录 → 商户回复」里标记为「有意向」的商户，是整个链路上最值钱的一批人。
必须当天转给 BD 电话跟进 —— 商户的采购决策窗口很短，隔天热度就凉了。
系统会自动把他们的生命周期推进到「有意向」并高亮显示。

### 几个设计取舍

**为什么用数据库队列而不是 Celery？**
短信发送是低频批量作业，不是高并发实时任务。数据库队列 + 单线程消费足够，
运维成本低一个数量级，且每条消息的状态天然可审计。

**为什么优先用变量短信而不是逐条发送？**
每条短信内容都不同（带门店名和专属短链），逐条发 500 条要 500 次 API 调用。
用创蓝的变量短信接口，把渲染前模板作为 `msg`、每条的变量值作为 `params`，
一次调用发完 500 条，速度差两个数量级。

**为什么去重要做三层？**
同一家店在「火锅」和「川菜」两个关键词下都会出现，网格化搜索的相邻格子边界上
也会重复返回。不去重就会让同一个老板收到多条相同短信 —— 这是投诉和退订的主要来源。
所以按 POI ID、归一化门店名+地址、手机号三层拦截。

## 对接主站

短信点击后，落地页会收到归因参数：

```
https://m.huodaizi.com/reg?hdz_src=sms&hdz_code=aB3xY7z&hdz_cid=12&hdz_mid=3456
```

主站在商户注册、开店、首单时回传，漏斗才能闭环：

```bash
curl -X POST https://your-domain/callback/conversion \
  -H 'Content-Type: application/json' \
  -d '{"phone":"13800138000","event_type":"first_order","amount":3200}'
```

`event_type` 可选 `register` / `open_shop` / `first_order` / `repeat_order`。
系统会按手机号自动关联回商户和活动，无需主站传活动 ID。

### 需要配到创蓝控制台的回调

```
状态报告推送   https://your-domain/callback/sms/report
上行回复推送   https://your-domain/callback/sms/reply
```

这两个回调不走 Token 鉴权（对方系统无法带我们的头），
生产环境请在网关层做 IP 白名单。

## 生产部署建议

- 数据库换 PostgreSQL：`DATABASE_URL=postgresql+psycopg://user:pass@host:5432/huodaizi`
- 用 gunicorn 起服务，但**发送调度器只能有一个进程运行**，
  多 worker 会重复发送。建议 `--workers 1` 或把调度器拆成独立进程。
- 商户手机号做静态加密存储，导出接口接公司审批流。
- 高德 Key 和创蓝密码走密钥管理服务，不要落在 `.env` 文件里。
